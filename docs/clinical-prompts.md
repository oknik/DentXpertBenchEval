# A5～A7 提示词与评测

7 份提示词保存在 `bench/prompts/`，内容来自提供的 txt。程序按题目的 `input.fields` 填充占位符；A5.2 另按医生记录的候选项 ID 筛选题面选项，不展示其角色、参考理由或正确诊断标签。A7.2 没有提供模板，本次不接入。

| 任务 | 输出字段 | 自动比较 | 待审核内容 |
| --- | --- | --- | --- |
| A5.1 | diagnoses、reason | 每题诊断集合 F1；独立模型评分理由 | 评分调用失败时需重试或人工审核 |
| A5.2 | diagnoses、reason、exclude_reason | 诊断 F1；两类理由分别评分 | 评分失败时重试或人工审核 |
| A5.3 | sufficiency、可选 reason | 项目约定标签映射；条件计分及不足理由评分 | 评分失败时重试或人工审核 |
| A6.1 | total、images | 去重总数完全匹配 50 分；逐图计数部分分 50 分 | 无（格式错误记为 invalid，总分 null） |
| A6.2 | diagnoses、reason | 诊断集合 F1 × 50；独立理由评分 0/25/50 | 评分调用失败时需重试或人工审核 |
| A6.3 | conditions | 暂无 | 补充条件 |
| A7.1 | plans | 独立整体评分 0/50/100 | 评分调用失败时需重试或人工审核 |

## 运行

要求 Python 3.10 或更新版本；在项目根目录运行：

```powershell
python -m pip install -e .
python -m unittest discover -s tests -v
python run.py --task A7.1 --dry-run --limit 1
```

`--dry-run` 不调用模型 API，不写评测结果；它使用明确标为格式示例的模拟回答，不衡量模型医学能力。测试中用临时生成的空白图片检查消息和红框，不需要原始影像。试运行遇到缺图、缺红框或无效回答时会返回非零退出码；下文记录的 A5.1 缺框题会被明确跳过。

A7.1 的题库是纯文字病例，因此试运行不需要图片。其他任务需要先提供题库对应的原始影像：

```powershell
python run.py --task A6.1 --image-root 'D:\你的数据集根目录' --dry-run --limit 1
```

图片根目录下应能直接找到题库路径中的数据集文件夹，例如 `FDTooth-C014/`、`COde-Dataset-C018/`。仓库只记录图片相对路径；本次检查未发现已跟踪的原始图片或影像压缩包，也未发现下载脚本或可直接获取全部影像的说明。默认根目录是项目旁的 `../公开数据集/公开数据集`，本次本地检查该目录不存在。`prepare.py` 只转换 JSON，不下载图片。需要课题组另行提供与题库路径匹配的数据。

准备好影像、模型 API 配置及密钥后，去掉 `--dry-run` 才会实际调用模型，建议先只跑一道题：

```powershell
python run.py --task A7.1 --model-config configs/model-gpt-6-luna.json --limit 1
python run.py --task A6.1 --image-root 'D:\你的数据集根目录' --model-config configs/model-gpt-6-luna.json --limit 1
```

正式调用可能产生 API 费用。模型配置与密钥读取方式沿用原项目，密钥保存在配置指定的文件或环境变量中。以上命令里的数据目录需要替换为实际路径。

`--task` 也可选 A5.1、A5.2、A5.3、A6.1、A6.2、A6.3。`--task all` 现在包括这 7 个任务；已有名称为 A1-A4 的批处理脚本仍按其原有任务范围工作。

## 输入与答案转换

- 所有 `input.images` 按原顺序发送，使用路径与 `evidence_media` 一一对应，在每张图前注明 M 编号，不把第 1 张固定称为 M01。
- A5.1、A5.2 根据各图的 `diagnosis_bbox` 绘制红框，原图保留，绘制结果写入 `preview/`。缺少坐标时记录输入错误，不自行推断范围。
- A7.1 仅接受文字病例，`images` 必须为空；性别、年龄、主诉、病史、检查、诊断和患者偏好按字段填充，未提供的内容明确注明未提供。
- A5.1/A6.2 将参考答案的 `selected_option_ids` 按输入选项转换为中文诊断；A5.2 仅展示 `differential_diagnoses` 中医生记录的候选项，按原输入选项顺序排列。将 `favored` 项作为诊断集合参考，`excluded` 项及其理由作为排除理由参考，其他选项不提供。模型若输出未展示的诊断，该题解析无效。
- A6.1 将 `total_count`/`image_counts` 转为 `total`/`images`，按实际图片发送顺序排列。
- A6.3 将补充条件类别转为提示词要求的中文标签；A7.1 将 `treatment_plans` 转为 `plans`。这些转换供评分和审核展示；A7.1 由整体评分判断，不按数组项数机械等价匹配。
- 原始答案保存在结果的 `reference_answer_native`；`reference_answer` 为转换后的展示或比较版本。
- 校验输出字段、类型、诊断是否来自候选列表、逐图计数是否覆盖全部 M 编号，以及 A5.3 理由字段的条件性。格式错误保存在 `parse_error`。

## 分数与审核

诊断选择报告集合完全匹配率及 micro precision/recall/F1；A6.1 报告去重总数完全匹配率、整组逐图计数完全匹配率，并另报逐图命中张数 / 题面影像数及部分分。无效回答单独计入 `invalid`（已启用总分的任务另计 `invalid_unscored`），不以 0 分代替医学得分；A6.1/A6.2 的无效答案不纳入相应客观指标分母；其他任务沿用各自原有指标统计规则。

这些比较保存在 `objective_metrics`。开放回答的待审字段列在 `pending_review_fields` 中，状态为 `pending_review`。A6.1 所有有效答案状态为 `scored`。

A5.1 每题总分 100：诊断得分为诊断集合 F1 × 50，理由得分为理由评分（0、1、2）÷ 2 × 50。F1 分别统计真阳性、假阳性、假阴性；模型若有未知诊断选项或格式错误，该题标记无效而不是默认为零分。

实际运行 A5.1～A5.3、A6.2、A7.1 时使用独立的理由/计划评分模型，默认读取 `configs/model-gpt-6-luna.json`，也可通过 `--judge-model-config` 指定另一个配置文件。被测模型与评分模型各自读取自己的配置及 API Key；A5.1 的评分提示词传递医生参考理由和模型理由，A5.2/A6.2 另传递对应诊断，A7.1 传递患者资料、医生参考计划数组和模型计划数组，要求输出 0、1、2 的评分及解释。结果包含评分模型名、原始回答、分数、解释及评分 token 使用量。调用或解析失败时保存 `reason_judge_error`，对应分数及该题总分保持 `null`，已算出的客观得分保留；不会默记为 0 分。自动评分需要课题组验证其与专家判断的一致性。

A5.2 每题100分：诊断集合 F1 ×50分；诊断理由和排除理由各按模型原始评分 ÷2 ×25分。一道题只发送一次理由评分请求，返回 `reason` 和 `exclude_reason` 两个对象，各包含整数 `score`（0/1/2）与文字 `explanation`。排除理由必须与医生明确排除的诊断及其依据对应。两类理由各限100字，原始医生参考理由不受模型输出字数限制。缺失或未知候选项 ID 明确报错，不退回完整选项列表。

A5.3 按本项目约定将 `supported` 映射为“充足”、`not_supported` 映射为“不足”。保留 `reference_answer_native` 和 `reference_answer` 中的原始标签、`reasoning` 文字及证据编号；`reference_label_mapping` 记录转换策略。提示词及标准输出仍使用“充足/不足”，模型的“不充足”作为“不足”的别名接收。“充足”时须省略理由；“不足”时须给出非空且不超过100字的理由。

A6.1 每题100分：`total` 与医生去重总数完全一致得50分；逐图得分 = 50 ×（逐图计数完全一致的张数 / 题面影像张数）。`total` 与 `count` 必须是严格非负整数，布尔值、浮点、负数均无效；`images` 必须按发送顺序覆盖全部 M 编号，重复、缺失、多余或乱序均判为无效；去重总数须满足“最大单图数 ≤ total ≤ 逐图之和”。无效答案记为 `invalid`，`case_score` 保持 `null`。A6.1 只做客观比较，不调用评分模型。

A6.2 每题100分：诊断集合 F1 × 50分；诊断理由由独立评分模型给 0/1/2 分，换算为 0/25/50分。诊断选项、去重和不超100字的要求与 A5.1 相同。评分请求同时传入医生/模型诊断及理由，要求核对理由与诊断的对应关系，不自行补充医生未提供的评分标准；颠倒核心事实或诊断角色时给0分。

A7.1 每题100分：由一次独立评分请求对完整模型计划数组、完整医生参考计划数组及题面患者资料作整体评分，0/1/2 分换算为 0/50/100分。2=关键处置、必要前提和顺序一致，无实质矛盾且无无依据的有创处置；1=部分匹配、缺少关键环节但无危险矛盾；0=核心处置错误、与患者资料/参考矛盾，或提出无依据且可能有害的有创处置。允许备选方案、同义表述、步骤拆分/合并及顺序等价，不按数组项数机械匹配。参考计划可能不完整，评分不得据此虚构参考要求或声称已由专家验证；结果中的评分解释作为审核依据。

A6.2、A7.1 的评分模型调用或解析失败时，已算出的客观分或已经解析的答案保留，对应字段分和 `case_score` 保持 `null`，状态为 `pending_review`；不会默认为0分。A6.2 与 A7.1 沿用 `reason_judgment`（含 `score`/`explanation`）以及 `reason_judge_model`、`reason_judge_response`、`reason_judge_token_usage`、`reason_judge_error` 字段；`reason_max_points` / `plan_max_points` 记录该题对应评分上限。

汇总中的 `skipped` 和 `skipped_cases` 单独记录跳过的题，不纳入有效题及总分分母；A5.1～A5.3、A6.1、A6.2、A7.1 的 `fully_scored` / `unscored` 区分已评分和未完成的题。未完成所有已尝试题的评分时，整体 `total_score`、`score_rate` 和 `average_score` 为 `null`；若部分题已完成，另行报告 `scored_total_score`、`scored_total_points` 和 `scored_average_score`。无效答案计入 `invalid` / `invalid_unscored`，不会当作0分。A5.3 通过 `objective_metrics.sufficiency` 报告判断准确率，A6.1 通过 `objective_metrics.images` 报告逐图命中张数与部分分。A6.3 尚未确认计分规则，最终分数保持 `null`。

上述 A5.3 映射是本项目明确采用的任务标签约定；输出保留转换记录，便于后续调整标注和审核。

结果 JSONL 的原始模型回答和转换后的回答均保留。可以用下面的命令重新汇总已有结果；该命令对 A6.1/A6.2/A7.1 从已保存的 `model_answer` 重算客观分，并复用已保存的 `reason_judgment`，不重新调用任何模型或评分接口，也不会静默丢弃已完成的评分：

```powershell
python evaluate.py 'results/实际结果文件名.jsonl' --task A6.1
```
